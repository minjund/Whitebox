# 스케치 011: 이해 패킷 오답 재확인 흐름

## 디자인 질문

모든 문항을 한 화면에서 제출한 뒤 맞힌 문제는 치우고, 틀린 문제의 해설·근거·미리 생성된 변형 문제를 어떤 구조로 보여줘야 재확인이 벌처럼 느껴지지 않고 실제 이해로 이어지는가?

## 보는 방법

`.planning/sketches/011-comprehension-remediation-flow/index.html`을 브라우저에서 연다.

## 변형

- **A: 카드 아래 확장** — 원래 오답 카드의 맥락을 유지하고 오른쪽 또는 아래에 해설과 변형 문제를 펼친다.
- **B: 오답 검토 데스크** — 최초 문제 화면을 치우고 오답 수와 진행 상태를 고정한 별도 검토 공간으로 전환한다.
- **C: 카드 제자리 변환** — 틀린 카드 자체가 해설과 변형 문제 카드로 바뀌어 화면 이동을 최소화한다.

## 동작하는 항목

- 세 문항 전체 제출과 미응답 검증
- 변형별 오답 화면 전환
- 맞힌 문항 제거와 오답 해설·근거 표시
- 미리 생성된 변형 문제 1회 제출
- 재오답 후 `이해했음` 처리와 오답 점수 유지
- `문제 오류` 문항의 분모·이해 부채 제외
- 최종 점수, 노드 이해 부채, 닫기·다시 열기
- 어두운/밝은 테마, 375/768/전체 폭, 설계 주석

## 무엇을 찾아봐야 할 것

- 첫 문제와 오답 해설의 관계를 가장 빨리 알아보는 안은 무엇인가?
- 오답이 여러 개여도 현재 재확인 위치와 남은 양이 명확한가?
- 변형 문제를 맞혔을 때 ‘이해가 복구됐다’는 감각이 자연스러운가?
- 재오답 점수를 유지하면서도 `이해했음`으로 부채만 해소된다는 차이가 보이는가?
