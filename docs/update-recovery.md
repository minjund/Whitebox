# 업데이트가 멈췄을 때

1.8.4는 업데이트 준비 실패 후 재시도, 오류 메시지 유지, 종료 순서와 macOS 설치 권한 확인을 개선합니다. 이미 설치된 구버전의 업데이트 코드는 새 버전을 설치하기 전에는 바뀌지 않습니다.

1.8.6은 미완성 내부 HTTP 요청 때문에 앱 종료가 멈추는 문제를 수정했습니다.
1.8.7부터는 새 버전이 있어도 **최신 버전 다시 확인** 버튼이 보이며, 15분마다
자동으로 조회합니다. 마지막 확인 시각은 성공한 조회만 표시하며, 실패하면
이전 버전 정보와 함께 오류를 보여 줍니다. 오래된 설치 파일을 실행하기 전에도
최신 릴리스를 다시 확인하고, 조회 실패 시 오래된 파일로 설치를 진행하지 않습니다.

1.8.1에서 1.8.2 안내가 계속 남는 경우 앱 시작 때 조회한 정보가 유지된 것일 수
있습니다. 2026-09-08 공식 1.8.1 설치본의 `app.asar`에 들어 있는 업데이트 코드를
실행해 공식 최신 1.8.6 설치 파일을 정상 선택하는 것을 확인했습니다. 파일 준비
오류라는 안내만으로 다운로드 실패라고 단정할 수 없습니다. 설치 도우미가 준비된
뒤 작업 종료 단계에서 실패할 수도 있습니다. 새 코드가 반영되기 전 구버전에서
막히는 사용자는 아래 수동 설치 방법으로 한 번 복구하세요.

## 기존 사용자

### PTY 종료 확인 오류가 반복되는 경우

`PTY process-tree 전체 종료를 확인하지 못했습니다.`는 설치 파일 다운로드 이후,
명령창 프로세스의 종료를 확인하는 단계에서 설치가 중단됐다는 뜻입니다.
명령창의 루트 프로세스가 종료돼도 전체 프로세스 그룹 종료가 확인되지 않으면
실패 상태를 유지합니다. 연결 프로그램은 앱 창을 다시 열어도 계속 실행될 수 있어
같은 실패 기록이 반복될 수 있습니다.

현재 소스는 같은 호스트가 보존한 PTY 종료 확인 정보를 사용해 macOS/Linux의
프로세스 그룹이 사라졌는지 다시 확인합니다. 이 재확인은 종료 신호를 보내지
않습니다. 그룹이 살아 있거나 조회가 실패하면 설치를 계속 차단하며, 호스트 재시작
후 저장 파일의 PID만으로 종료를 시도하지 않습니다. 비동기 정리 이후에도
업데이트 대상 범위를 유지해 이전 호스트의 기록을 새로 종료하려 하지 않습니다.
이 수정은 새 설치본을 적용하기 전 구버전의 실행 중인 호스트에 반영되지 않습니다.

새로 시작하는 설치본의 명령창 호스트는 앱 설치 폴더 밖의 버전별 실행 환경을
사용합니다. 업데이트는 이 호스트를 종료하지 않고 화면 연결만 끊으며, 설치 후
자동으로 다시 열린 Whitebox가 같은 호스트와 PTY에 연결합니다. 일반 PTY도
이 경로에서는 계속 실행됩니다. 실행 환경은 해당 호스트가 사용하는 동안 보존합니다.
Windows에서는 설치기의 프로그램 이름 기반 종료 대상에서 제외되도록 독립
호스트를 `WhiteboxTerminalHost.exe`로 실행합니다. 설치 폴더 밖에 있더라도
GUI와 실행 파일 이름이 같으면 작업 보존이 가능한 호스트로 인정하지 않습니다.

이미 실행 중인 구버전 호스트가 설치 폴더에 묶여 있거나 직접 실행 작업이 아직
진행 중이면 작업을 강제 종료하는 대신 설치를 보류합니다. 기존 프로세스를
새 호스트로 이동시켰다고 가정하지 않습니다. 작업 완료 후 새 설치본으로 전환해야
이후 명령창부터 독립 실행 환경을 사용합니다.

자동 설치 경로에서는 설치 도우미가 새 앱을 직접 실행하므로 사용자가 프로그램을
다시 열 필요가 없습니다. 새 버전과 해당 재실행 프로세스의 화면 준비 신호를
확인한 뒤에만 설치 성공으로 처리합니다. 재실행은 포커스를 가져오지 않습니다.
작업 완료 알림이 실패해도 본 창을 자동으로 열지 않으며, 자동 팝업은 기본으로
꺼집니다. 설정에서 새로 켠 팝업도 다른 창의 포커스를 가져오지 않습니다.

- 업데이트가 정상적으로 완료되면 별도 조치가 필요 없습니다.
- 버튼이 반응하지 않거나 앱이 닫힌 후 다시 열리지 않으면, 진행 중인 작업을 저장한 뒤 Whitebox를 완전히 종료하고 최신 버전을 수동 설치하세요.
- Windows: [공식 최신 릴리스](https://github.com/minjund/Whitebox/releases/latest)의 `Whitebox-Setup-버전.exe`를 실행합니다. 가능하면 기존 설치 위치를 사용하고 설치 완료 후 시작 메뉴에서 Whitebox를 실행하세요.
- macOS: Apple Silicon은 `arm64.dmg`, Intel은 `x64.dmg`를 받습니다. Whitebox를 종료하고 DMG의 Whitebox.app을 Applications에 복사해 기존 앱을 교체한 뒤 Applications에서 실행하세요. 쓰기 권한을 요청하면 macOS의 인증 절차를 따르세요.
- 앱 데이터 폴더를 삭제하거나 기존 버전을 먼저 제거할 필요는 없습니다. 설정·대화 데이터 폴더를 유지하세요.
- 개발 빌드(`release/win-unpacked` 등)를 실행하던 경우에는 업데이트 후 공식 설치 위치의 앱을 실행하세요. 이전 작업 폴더의 실행 파일은 별도로 남을 수 있습니다.

## 지원 시 확인할 정보

현재 버전, 운영체제와 CPU, 오류 메시지를 확인하세요. 1.8.4 이후에는 앱 데이터의 `updates/install-attempts.jsonl`에 준비·실패·설치 도우미 시작 단계가 기록됩니다. `updates/install-update.log`에는 설치와 재실행 결과가 기록됩니다. 이전 LoadToAgent 사용자는 기존 데이터 폴더에 로그가 남을 수 있습니다.

## 호환성 검증 경로

| 시작 버전 | 경로 |
| --- | --- |
| LoadToAgent 1.6.3–1.6.14, 1.6.16–1.6.22 | 불변 공식 1.6.23 브리지 → 현재 버전 |
| Whitebox 1.7.3, 1.7.4 | 공식 수동 설치 별칭 |
| Whitebox 1.7.5 이후 | 공식 자동 설치기, 실패 시 위 수동 복구 절차 |

1.6.15는 공개된 버전이 아닙니다. 릴리스 검사는 공식 1.7.3·1.7.4·1.7.5 및 1.6.3 → 1.6.23 경로를 새 격리 환경에서 실행합니다. 후보 Windows 패키지는 실제 UI 버튼의 실패·재시도·재설치까지 검사하고, macOS 후보 패키지도 실제 버튼으로 DMG 설치와 renderer-ready 재실행을 검사합니다.
