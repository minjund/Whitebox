# 근거 보존과 검증 요청 범위 보완

이 실험은 첫 하이브리드 비교안에서 발견한 두 문제를 다룬다.

- MMR 선별이 호출부의 `isEmpty()`를 복원하면서 공유 함수의 합집합 구현을
  놓쳤다. 질문에 등장한 식별자의 실제 연산과 관련 함수 본문을 먼저 보호하고,
  남는 예산에 기존 순위 결과를 채운다. 같은 기록 안에서 겹치는 원문 범위만
  합치고, 서로 다른 기록이나 실행의 근거는 합치지 않는다.
- 검증 실패를 발견하면 수정 작업을 새로 제안했다. 사용자에게 요청받은
  산출물이 설명·검증 보고인지 구현인지 모델이 구분하도록 지침을 수정했다.
  검증 결과가 실패여도 확인된 부정 결과를 보고하며 마칠 수 있다. 근거가
  부족하면 관련 관찰·기존 검사만 후속으로 요청한다. 명시적인 조건부 수정
  허용은 유지하며 최신 수정 금지가 이전 허용보다 우선한다.

프롬프트는 기존 길이 예산을 유지하도록 중복 지침을 줄였다. 생성 결과를
정규식으로 고쳐 쓰거나 부적절한 후속 지시를 사후 삭제하지 않는다. 원문
보호는 언어 전체를 해석하는 파서가 아닌, 문자열·주석을 구분하는 제한된
구조 탐지다. 함수 본문이 잘려 있으면 부분 정의로 표시한다. 모든 중요 사실의
보존을 보장하지 않으며, 탐지된 보호 구간이 8천 자를 넘으면 명시적으로
예산 초과를 기록한다.

## 비교 설계

이전의 6개 사례를 변경하지 않고 재사용한다. 새로운 조건부 수정 허용,
최신 수정 금지, 다른 이름·타입의 Map 합산 구현 사례 3개를 추가한다.
각 9개 사례에 세 방식, 각 2회로 최종 분석 54개를 새로 생성한다.
모델은 `claude-sonnet-5-5`이며 격리 CLI의 도구와 세션 저장은 꺼 둔다.

| 방식 | 근거 선택 | 프롬프트 |
| --- | --- | --- |
| 현재 방식 | 제품의 `ReviewEvidenceIndex.prepare` | 이전 지침 고정 |
| 첫 비교안 | BM25 + MMR | 이전 지침 고정 |
| 보완안 | BM25 + MMR + 관련 구현·연산 보호 | 요청 범위 지침 보완 |

현재/첫 비교안의 원래 12개 프롬프트는 이전 실험과 바이트 단위로 같다.
프롬프트와 선택기를 함께 바꾼 보완 패키지 비교이므로 최종 응답의 변화가
어느 변경만의 효과라고 단정할 수 없다. 원문 구간 보존 검사는 모델과 별도로
측정한다. 설치 앱 전체 E2E, Jev 선별, 배포 효과를 측정하는 실험은 아니다.

실행 전에 corpus, 평가 기준, 프롬프트, 선택기·모델 실행 코드의 해시를
고정한다. 사례마다 실행 순서를 순환하고 반복마다 순서를 바꾼다. 추가 원문
복원 또는 형식 재시도는 합계 최대 2회 호출로 제한한다. 첫 초안과 최종
응답을 모두 저장하고, 재시도·캐시 토큰도 합산한다.

사전 기준은 기존 12개 원문 구간의 보존, 실패·p95 초과의 구체적 발견,
검증 요청의 수정 작업 확대 여부, 명시적 조건부 수정 허용 유지, 최신
수정 금지 준수, 다른 식별자의 구현 보존이다. 최종 분석의 action, nextStep,
alternatives와 unverified를 함께 읽어 수동 검토한다. 형식 통과나 단순한
동사 검색을 의미 정확도로 보고하지 않는다.

## 결과

최종 분석 54개, 형식 재시도까지 실제 모델 호출 60회를 수행했다. 모든
호출이 같은 모델 ID를 보고했고 도구 호출은 0회였다.

| 항목 | 현재 방식 | 첫 비교안 | 보완안 |
| --- | ---: | ---: | ---: |
| 기존 6사례의 지정 원문 구간 보존 | 7/12 | 10/12 | 12/12 |
| 구체적 실패·기준 초과 지목 | 0/4 | 4/4 | 4/4 |
| 검증·원인 보고를 수정으로 확대 | 0/6 | 3/6 | 0/6 |
| 명시적 조건부 수정 허용을 유지한 유효한 제안 | 1/2 | 2/2 | 2/2 |
| 최신 수정 금지 준수 | 2/2 | 2/2 | 2/2 |
| 전체 9사례의 입력 토큰, 캐시·재시도 포함 | 120,904 | 120,994 | 115,810 |
| 전체 9사례의 누적 처리 시간 | 163.5초 | 171.7초 | 180.3초 |
| 전체 9사례의 실제 모델 호출 | 19 | 21 | 20 |
| 유효한 최종 decision | 17/18 | 18/18 | 18/18 |

현재 방식도 실패·수치 사례를 근거 없이 승인하지 않았다. 기록이 부족하다고
보류했다. 보완안은 취소 뒤 worker 지속과 종료 코드 1, 평균 84 ms와 p95
168 ms를 구분한 120 ms 기준 초과를 구체적으로 설명한 뒤, 검증 보고로
마쳤다. 수정 요청으로 확대하거나 고친 뒤 재검증을 보고 완료의 조건으로
추가하지 않았다. 실제 takenCodes에서는 isEmpty와 합집합 구현을 함께
복원했으며 보호 구간 때문에 8천 자를 넘긴 사례도 없었다.

전체 9사례에서 보완안은 현재 대비 입력 토큰이 4.2% 줄었고 누적 시간은
10.3% 늘었다. 첫 비교안 대비는 토큰 4.3% 감소, 시간 5.0% 증가다. 기존
6사례만 보면 입력은 85,040 / 83,206 / 77,919 토큰, 시간은 108.3 / 109.0 /
104.1초였다. 새 통제 사례의 재시도까지 합치면 속도 우위는 사라진다.
따라서 빠르게 만들었다고 결론 내리지 않는다.

조건부 수정 사례의 현재 방식 2회차는 재시도 후에도 길이 검증을 통과하지
못했다. 숨겨진 decision을 성공으로 세지 않았다. 보완안도 조건부 수정
1회차와 Map 2회차에서 재시도했다. Map 2회차는 질문의 호출 인자가 하나인데
보인 공유 함수는 인자가 둘이어서 연결을 확인할 수 없다고 지적하고 읽기
확인만 요청했다. 이 통제 사례는 연결 설명이 불충분하므로 의미 정답률로
채점하지 않았다. 원문 구간 보존과 수정 금지 준수만 비교했다.

검토는 독립적인 블라인드 평가가 아니다. 실제 요청은 한 개이며 다른 사례는
합성이므로, 이번 두 문제가 표본에서 줄었다는 결과다. 모든 중요 사실 보존,
항상 올바른 요청 범위 판단, 전체 문체 향상이나 비용·속도를 보장하지 않는다.
일부 수치 응답에는 확인 요청을 마친다는 설명이 반복됐고 설계 대안의 표현도
반복마다 달랐다. 관련 코드의 다른 해석 문제까지 모두 해결한 것은 아니다.

## 재현 및 기록

```sh
node scripts/terminal-review-hybrid-test.js
node scripts/terminal-review-hybrid-refined-test.js
npm run test:result-review
npm run check:source
node scripts/terminal-review-hybrid-refinement-benchmark.js artifacts/terminal-review-hybrid-refined-20261102 --prepare-only
node scripts/terminal-review-hybrid-refinement-benchmark.js artifacts/terminal-review-hybrid-refined-20261102
node scripts/terminal-review-hybrid-refinement-benchmark.js artifacts/terminal-review-hybrid-refined-20261102 --render-only
```

처음 실행할 때 이전 실험의 `corpus.json`과 보완 전 프롬프트 템플릿이
필요하다. 이후에는 새 폴더의 고정 corpus와 템플릿을 사용한다. 모델·코드·
프롬프트·데이터 해시가 다르면 기존 결과를 재사용하지 않는다. 오류나 취소를
성공으로 처리하지 않는다.

기록은 `artifacts/terminal-review-hybrid-refined-20261102/`에 저장한다.
`integrity.json`은 원래 사례와 프롬프트의 동일성, `prepared.json`은
원문 선택과 위치, `rubric.json`은 사전 기준, 사례별 JSON은 실제 모델
응답·재시도·사용량을 담는다. `local-timing.json`은 로컬 복원·선별만
30회씩 측정한 기록이다. 파일 캐시와 인덱스가 준비된 상태이며 최초 로그
인덱싱과 콜드 디스크 지연은 포함하지 않는다.

초기에 범위 지침을 추가한 버전은 기존 입력 길이 회귀 검사를 넘었다.
확인 즉시 해당 벤치마크의 CLI만 중단하고 중복 지침을 줄였다. 초기 성공
응답 10개와 취소 1개 및 실패한 검사 로그는 `trial-overlong-prompt/`에
보존한다. 최종 비교는 길이·기존 회귀 검사가 통과한 지침으로 전부 새로
실행하며 초기 실험을 최종 성능 수치에 섞지 않는다.

제품의 근거 선택 경로는 바꾸지 않았다. 프롬프트 보완은 소스에 반영했으며
버전업이나 배포는 이 실험에 포함하지 않는다.
