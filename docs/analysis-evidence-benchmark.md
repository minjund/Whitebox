# 근거 선별 알고리즘 비교 실험

2026-11-02에 현재 근거 선택과 비교용 하이브리드 선택을 실제
`claude-sonnet-5-5`로 비교했다. 제품의 선택 경로나 설정은 바꾸지 않았다.

현재 방식은 `ReviewEvidenceIndex.prepare`를 그대로 실행한다. 중요 단어가
있는 원문 기록을 먼저 골라 최대 4개, 합계 8천 자를 복원한다. 비교안은
같은 요청에 속한 공개 기록을 해시 검증 후 로컬에서 읽고, 실패·조건을
우선 보존한 뒤 BM25 관련도와 TF-IDF 코사인 유사도의 MMR로 원문 구간을
고른다. 요청과 최종 답변은 공통 입력에 남긴다. 답변의 단어는 검색 보조어로만
쓰고, 사실이나 사용자 승인으로 취급하지 않는다. 짧은 도구 기록은 보존한다.
원문 구간에는 기록 ID, 역할, 요청 ID와 문자 위치가 붙는다.

설치된 2.0.11의 `src/terminalReviewEvidence.js`와 현재 소스는 SHA-256이
동일했다. 분석 프롬프트는 직전 개선 버전을 양쪽에 동일하게 사용했다.
따라서 이 실험은 근거 선택 효과를 분리한 비교이며 설치 앱 전체 E2E나
Jev 라우팅, 배포 성능을 평가한 결과는 아니다.

실제 takenCodes 요청 1개, 짧은 통제 사례 2개, 합성 스트레스 사례 3개를
각 방식으로 2회씩 교차 순서로 실행했다. 합성 사례 중 하나는 실제 사례에
반복 읽기 로그를 붙인 파생본이다. 모델 호출 전에 데이터, 원문 근거 기준,
프롬프트 해시를 고정했다. 모델 출력 확인 후 선택 규칙을 바꾸지 않았다.

| 항목 | 현재 | 비교안 |
| --- | ---: | ---: |
| 최종 분석 수 | 12 | 12 |
| 실제 모델 호출 수 | 12 | 13 |
| 모든 호출의 입력 토큰, 캐시 생성·읽기 포함 | 85,046 | 83,203 |
| 누적 선택·모델·재시도 시간 | 102.7초 | 107.2초 |
| 지정한 12개 원문 구간 보존 | 7 | 10 |
| 합성 충돌 사례에서 구체적 실패·초과 지목 | 0/4 | 4/4 |
| 같은 충돌 사례에서 근거 없는 완료 승인 | 0/4 | 0/4 |

입력 토큰은 2.2% 줄었고 누적 시간은 4.4% 늘었다. 비교안의 형식 재시도
1회도 포함한 값이다. 실제 takenCodes 사례에서는 비교안 입력 토큰이
약 5.6% 늘었으며, 최종 설명의 뚜렷한 우위는 없었다. isEmpty 구현을
확보하는 대신 합집합 구현 구간을 놓쳤다. 현재 방식도 반복 읽기 잡음은
걸러냈고, 짧은 두 사례의 최종 설명은 거의 같았다.

합성 실패·수치 사례에서 현재 방식은 완료를 보류하며 근거 확인을 요청했다.
비교안은 취소 후 worker 지속과 종료 코드 1, 변경 후 p95 168 ms의
120 ms 기준 초과를 구체적으로 지목했다. 그러나 최종 후속 제안 3개가
검증 요청을 수정 작업으로 넓혔다. 이는 실제 수정 실행이 아니라 생성된
후속 지시의 문제다. 내용 검토는 모든 최종 출력과 재시도 전 초안을 읽은
주 에이전트의 수동 검토이며 독립적인 블라인드 평가가 아니다. 요청 범위
확대는 공통 프롬프트에 대한 추가 검토 항목으로, 사전 고정 품질 점수가 아니다.

로컬 복원·선별만 따로 30회 측정한 중앙값은 실제 takenCodes에서
현재 0.28 ms, 비교안 0.79 ms였다. 합성 장문 사례에서는 비교안이
약 0.72~2.53 ms였다. 준비된 인덱스와 따뜻한 파일 캐시의 측정으로,
초기 로그 인덱싱과 콜드 디스크 지연은 포함하지 않는다.

전면 교체를 뒷받침하는 결과는 아니다. 긴 로그에 한해 관련 함수·상충
결과의 누락을 다시 복원하는 경로와 검증 요청의 범위 보존을 보완한 뒤,
더 많은 실제 세션으로 검증할 필요가 있다. 지정 구간 보존율은 의미 정확도가
아니며, 토큰 합계는 원화 비용이 아니다. 예산을 넘는 필수 구간은 버리지
않고 명시적으로 초과 처리하므로 이런 사례의 비용도 별도 확인해야 한다.

## 재현

```sh
node scripts/terminal-review-hybrid-test.js
node scripts/terminal-review-hybrid-benchmark.js artifacts/terminal-review-hybrid-20261102 --prepare-only
node scripts/terminal-review-hybrid-benchmark.js artifacts/terminal-review-hybrid-20261102
node scripts/terminal-review-hybrid-benchmark.js artifacts/terminal-review-hybrid-20261102 --render-only
npm run test:result-review
npm run check:source
```

최초 준비는 이 사용자가 지정한 실제 Whitebox 작업과 정확한 Claude
요청을 읽는다. 다른 환경에서는 동일 스키마의 `corpus.json`을 먼저 제공해야
한다. 기존 corpus가 있으면 원래 세션을 다시 읽지 않는다. 데이터, 프롬프트,
선택기 해시가 달라지면 기존 출력 재사용을 거부한다. 각 호출은 새 임시
디렉터리에서 도구와 세션 저장을 끈 제품의 격리 CLI 명령으로 수행한다.
선택적 원문 추가 복원과 형식 재시도는 제품과 같은 최대 2회 호출 제한을
사용한다. 시간 초과와 모델 오류는 성공으로 세지 않는다.

보고서와 데이터는 무시되는 `artifacts/terminal-review-hybrid-20261102/`에
저장한다. `corpus.json`과 `manifest.json`은 고정 입력, `prepared.json`은
선택 결과, 사례별 JSON은 실제 응답·사용량·추가 복원·재시도 기록이다.
`environment.json`은 설치 앱 비교 범위, `assessment.json`은 내용 검토,
`local-timing.json`은 로컬 반복 측정이다. `preflight-selection/`에는 모델 호출
전에 발견해 수정한 짧은 기록 누락 문제의 초기 선택 결과도 남겨 두었다.

검증한 항목은 선택기의 원문 위치·역할 보존, 드문 실패·수치 조건, 예산
초과 표시, 상충 결과, 짧은 다국어 기록, 요청 범위 분리, 원문 변조 거부,
캐시 포함 사용량 계산과 기존 분석 회귀 검사다. 모든 모델 보고는 같은
모델 ID였고 도구 호출은 0회였다. HTML은 로컬 파일로 저장했으며 브라우저의
file URL 제한으로 시각 미리보기는 확인하지 못했다.
